# IRTest —— 四方向红外避障测试

> 独立工程，只做一件事：**哪一侧的红外看到东西，车就朝相反方向平移。**
> 不碰 `Template.uvprojx`，也没有改动任何原有源文件。

---

## 它到底做什么

| 检测到障碍的一侧 | 车的动作 | 轮速组合 `m201..m204` |
|---|---|---|
| 前 | 后退 | `(-,-,-,-)` |
| 后 | 前进 | `(+,+,+,+)` |
| 左 | 右移 | `(-,+,-,+)` |
| 右 | 左移 | `(+,-,+,-)` |

每一侧有两只探头，**任意一只触发就算这一侧有障碍**：

| 侧 | 探头 1 | 探头 2 |
|---|---|---|
| 前 | `FL = PD13`（左） | `FR = PE12`（右） |
| 后 | `BL = PB7`（左） | `BR = PE4`（右） |
| 左 | `LU = PD14`（前） | `LD = PB8`（后） |
| 右 | `RU = PE11`（前） | `RD = PE3`（后） |

八路都是 GPIO 输入 + 上拉，**低电平 = 检测到障碍**（这类红外模块常见）。
没东西时四个轮子停着，绿灯常亮。

> 以上是 2026-10-20 实测接线。某一路接反或接错，只改 `irtest_main.c`
> 顶部对应的 `IR_FRONT_L` 等宏即可，逻辑不用动。

### 多侧同时触发

程序把前后、左右分别合成一个方向量，再做矢量和：

| 同时触发 | 结果 |
|---|---|
| 前 + 左 | 后退 + 右移（斜着退，每个轴速度减半） |
| 前 + 右 | 后退 + 左移 |
| 后 + 左 | 前进 + 右移 |
| 后 + 右 | 前进 + 左移 |
| 前 + 后 | 前后抵消，这一轴停（通常四轮全停） |
| 左 + 右 | 左右抵消，这一轴停 |
| 三侧 / 四侧 | 剩下那一轴动，或者全停 |

> 斜着走时会有两个轮子的指令是 0，这是正常的：全向底盘 45 度平移本来就只靠
> 另外两个轮子驱动，那两个轮子是被动滚动的。

## 怎么测

### 第一步：确认八路都能变

串口 `USART1`，19200 8N1，`PA9 = TX`，每 500ms 一行：

```
IR: FL0 FR0 BL0 BR0 LU0 LD0 RU0 RD0 | F0 B0 L0 R0 | vx  0 vy  0 | m201   0 m202   0 m203   0 m204   0
```

- `FL..RD`：八路探头的**瞬时**电平（1 = 看到东西）。
- `F B L R`：四侧**去抖后**的结果。
- `vx / vy`：算出来的运动方向。`vx>0` 前进，`vy>0` 左移。
- `m201..m204`：真正下发到驱动板的四个轮速。

依次用手挡每一侧，确认：

| 挡哪里 | 期望串口 | 期望轮子 |
|---|---|---|
| 前（左或右任一只） | `FL1` 或 `FR1`，`F1`，`vx -1` | 四轮同时反转（后退） |
| 后（左或右任一只） | `BL1` 或 `BR1`，`B1`，`vx +1` | 四轮同时正转（前进） |
| 左（前或后任一只） | `LU1` 或 `LD1`，`L1`，`vy -1` | `m201/m203` 负、`m202/m204` 正（右移） |
| 右（前或后任一只） | `RU1` 或 `RD1`，`R1`，`vy +1` | `m201/m203` 正、`m202/m204` 负（左移） |
| 手拿开 | 全 0，`vx/vy = 0` | 四轮停，绿灯常亮 |

如果挡某一侧时变的是**别的**探头位，说明那一路的接线和上表不一致，
按实际变化改 `irtest_main.c` 顶部对应的 `IR_xxx` 宏即可。

### 第二步：实际避障

把车放在地上，速度 `15`，按下面的顺序过一遍：

- [ ] 前面慢慢靠近障碍 → 车后退；障碍拿开 → 停
- [ ] 后面靠近障碍 → 车前进；拿开 → 停
- [ ] 左侧靠近障碍 → 车右移；拿开 → 停
- [ ] 右侧靠近障碍 → 车左移；拿开 → 停
- [ ] 前 + 左同时挡 → 斜着后退（右后方）
- [ ] 前 + 后同时挡 → 停住（前后抵消）
- [ ] 用纸箱从远处慢慢推近，记录每一侧能触发的距离

> 红外模块上一般有一个电位器，可以调检测距离。四块/八只的灵敏度不一定一致，
> 以“手在 10~20cm 内能稳定触发、平时不误触发”为准。

## 第一次上车要确认的三件事

### 1. 极性

上电后什么都没挡，串口却显示 `FL1 FR1 ...` 全 1：

```
#define IR_ACTIVE_LOW   0
```

改成 0 重新编译。只有个别一路常 1，就是那一路的接线/探头问题，不是极性。

### 2. 前后 / 左右方向

正常情况下 `IR_SIGN_VX` / `IR_SIGN_VY` 都是 `+1`。
如果**前面挡东西，车反而往前顶**：

- 先确认四轮方向仍和 `MoveTest` 一致（正速度前进）；
- 四轮没问题，再把 `IR_SIGN_VX` 改成 `-1`。

左右同理。不要同时改两个符号，否则分不清是哪边的问题。

### 3. 检测距离

红外模块的探测距离和地面颜色、反光、环境光都有关系：

- 车贴着地面时，侧面的探头可能照到地板，一直误触发 → 把探头稍微抬高或调低灵敏度；
- 黑色障碍物比白色更难反射 → 用比赛实际会遇到的障碍物测；
- 距离调到 10~20cm 比较合适，太远会在场地里被无关物体触发。

## 停下来还不对，按这个顺序查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 上电后串口没输出 | USART1 没接对 / 程序没跑 | 查 PA9、GND、19200 8N1 |
| 八路全 1，没东西也触发 | 极性反了，或模块供电不对 | 先改 `IR_ACTIVE_LOW 0` |
| 八路全 0，挡东西也不变 | 模块没供电 / 输出没接 / 地没共 | 查模块 5V、GND、信号线 |
| 只有一路不变 | 那一路的探头或线有问题 | 对调探头/线，确认是探头还是 MCU 引脚 |
| 前面挡，车前进 | 前后符号反了 | `IR_SIGN_VX -1` |
| 左边挡，车左移 | 左右符号反了 | `IR_SIGN_VY -1` |
| 车一直抖（走一下停一下） | 刚好在检测临界距离 | 调电位器加大回差，或把 `IR_DEBOUNCE` 加到 3 |
| 红绿急闪 | 写四轮板失败 | 查 PF5/PF6 和驱动板供电 |
| 用 pyocd 复位后 PC 在 `0x1FFF3xxx`、VTOR=`0x1FFF0000` | 软件复位进了 ST 系统 bootloader，不是你的程序 | 按板上复位键，或用 `-O reset_type=hw` 硬件复位；正常上电不会这样 |
| 编译报 `expected an identifier` 在 `GPIO_InitTypeDef` 那行 | `imu.h` 里有 `#define g 9.8`，局部变量不能叫 `g` | 本程序已改名 `gpio`；自己加代码时别用单字母 `g` |

## 实测记录（2026-10-20）

### 八路接线与逐路结果

| 侧 | 探头 | 引脚 | 挡板测试 |
|---|---|---|---|
| 前 | 前左 `FL` | **PD13** | ✅ 正常 |
| 前 | 前右 `FR` | **PE12** | ✅ 正常 |
| 后 | 后左 `BL` | **PB7** | ❌ 挡板无反应，全程为 1 |
| 后 | 后右 `BR` | **PE4** | ✅ 正常 |
| 左 | 左前 `LU` | **PD14** | ✅ 正常 |
| 左 | 左后 `LD` | **PB8** | ✅ 正常 |
| 右 | 右前 `RU` | **PE11** | ✅ 正常 |
| 右 | 右后 `RD` | **PE3** | ✅ 正常 |

- 极性：八路空闲为高、挡板拉低（E18-D80NK，NPN 低电平有效），
  `IR_ACTIVE_LOW = 1` 正确；静止时八路全 1，绿灯常亮。
- 测试方法：ST-Link 直接读 `GPIOB/GPIOD/GPIOE` 的 IDR，100 ms 采样；
  按侧挡板，观察对应位是否拉低。前/左/右三侧都是两只探头同时响应，
  后侧只有 `BR` 响应，`BL` 从未变化。
- 结论：**7/8 路有数据**。后左 PB7 这一路要查探头供电、信号线、电位器；
  后侧避障暂不使用，先不处理。
- 以后要修时：把后左、后右的信号线在 MCU 端对调（`PB7` ↔ `PE4`），
  看故障跟着探头走还是留在 PB7，就能区分是探头/线的问题还是引脚的问题。

### 和主固件的差异

- `APP/sensor/sensor.h` 里的 `*_OBSTACLE` 宏仍是旧引脚
  （PD6/PF1/PF4/PD3/PD4/PD5/PF3/PF2），和实测接线不符。
- `User/main.c` 调用 `LED_EX_Init()` 会把 PB8 配成推挽输出（`LED_TEAM`），
  和左后红外的 PB8 冲突。主固件要用避障，必须先去掉这句或改 `LED_TEAM` 引脚。

## 这个工程里有什么

```
IRTest\
    irtest_main.c        测试程序（GBK + CRLF，和工程里其它 .c 一致）
    IRTest.uvprojx       工程文件，文件清单沿用 TraceTest
    IRTest.uvoptx        调试器配置（ST-Link / SWD）
    Obj\IRTest.hex       编译产物
```

工程清单里仍然带着四块灰阶驱动（`B/F/L/R_GREY_driver.c`）和 `sensor.c`，
它们链接时要 `reverse()`，而 `reverse()` 本来在 `APP\trace\trace.c` ——
那个文件不在本工程里。所以 `irtest_main.c` 里补了一份 `reverse()` 定义。
删掉会报：

```
L6218E: Undefined symbol reverse (referred from b_grey_driver.o)
```

本程序**不使用灰阶**，也不调用 `OBSTACLE_Init()`；红外 GPIO 在
`IR_SensorInit()` 里单独初始化，因此不会和灰阶的软 I²C 抢引脚。

# TraceTest —— 四方向循迹测试

> 独立工程，只做「一块灰阶 → 纠偏 → 四个轮子」这一件事。
> 在 Keil 里改 `TRACE_DIR` 一行，就能切换前进 / 后退 / 左移 / 右移循迹；
> 程序只会初始化并读取选中的那一块传感器。
> 不碰 `Template.uvprojx`，也没有改动任何原有源文件。

---

## 它到底做什么

先选方向，然后程序只读那一块灰阶：

| `TRACE_DIR` | 车怎么走 | 用哪块灰阶 | 软 I²C 引脚 |
|---|---|---|---|
| `TRACE_DIR_FRONT` | 前进 | 前灰阶 | PB13 = SCL，PB14 = SDA |
| `TRACE_DIR_BACK` | 后退 | 后灰阶 | PD1 = SCL，PD2 = SDA |
| `TRACE_DIR_LEFT` | 左移 | 左灰阶 | PC8 = SCL，PC9 = SDA |
| `TRACE_DIR_RIGHT` | 右移 | 右灰阶 | PC3 = SCL，PC2 = SDA |

四块地址都是 `0x4F`（8 位形式 `0x9E`），各自一条独立软 I²C 总线。

控制律和原来一样：

- 线偏到探头一头 → 车朝那一头转；偏到另一头 → 朝另一头转。
- **转向**同时修「车心回到线上」和「车头顺线」，所以一块传感器就够。
- 走到十字 / 丁字路口（探头 4、5 黑，且 1~4 或 5~8 全黑）时不纠偏，直着过。
- 丢线后按最后一次的纠偏方向继续走 2 秒，还找不回来才停。
- 上电先等线：选中的那块灰阶没看到线时，四个轮子停着、红灯常亮；
  线一进探头范围就自动起步。

轮速是「该方向的基础速度 + 原地旋转纠偏」：

| 方向 | 基础速度 `b201..b204` |
|---|---|
| 前进 | `(+,+,+,+)` |
| 后退 | `(-,-,-,-)` |
| 左移 | `(+,-,+,-)` |
| 右移 | `(-,+,-,+)` |

```
m201 = b201 + w    m202 = b202 + w
m203 = b203 - w    m204 = b204 - w
```

`(+1,+1,-1,-1)` 这一组才是原地旋转；`(+,-,-,+)` 是空转组，发下去车不动，
不要用错。

## 上车怎么摆

| 方向 | 怎么放车 | 车会往哪走 |
|---|---|---|
| 前进 | 黑线压在前灰阶探头中间，车头顺线 | 向前 |
| 后退 | 黑线压在后灰阶探头中间，车头仍顺线 | 向后 |
| 左移 | 黑线压在左灰阶探头中间，线沿车的左右方向 | 向左 |
| 右移 | 黑线压在右灰阶探头中间，线沿车的左右方向 | 向右 |

要点：

- **只把线放在选中的那块传感器下面**，其它三块不用管。
- 左移/右移时，线是「横着」从车侧面穿过的；车走的方向就是线延伸的方向。
- 起步时线不在探头下面，它不会乱跑：红灯常亮、四轮停着等；
  把车往线上推一点就自己起步，不用复位。
- 想重来就按复位。

> 2026-10-20 实测：**四块八路巡线模块（前/后/左/右）均正常**。
> 2026-10-21 实车确认：四个方向的 `TRACE_SIGN_FRONT / BACK / LEFT / RIGHT`
> 当前都取 `-1`，前进、后退、左移、右移循迹均正常，不需要再翻符号。

> 前灰阶能看见的横向范围约 ±28 mm。后/左/右三块同理，具体范围以实车为准。

## LED 和串口

| 现象 | 含义 |
|---|---|
| 绿灯**常亮** | 线在死区里，不用纠偏 |
| 绿灯**慢闪**（200ms） | 正在纠偏 |
| 绿灯**快闪**（60ms） | 压在横向线 / 路口上，这一帧直着过 |
| 红灯**快闪** | 丢线了，还在按最后的转向继续走（2 秒内） |
| 红灯**常亮** | 还没看到线（等待起步），或者丢线超时已停车 |
| **红绿交替急闪** | I²C 写四轮驱动板失败（会重试 3 次 + 总线恢复） |

串口 `USART1`，19200 8N1，`PA9` = TX，每 500ms 一行：

```
Trace[FRONT]: raw E7 E  -3 w  3 | m201  18 m202  18 m203  12 m204  12 | CORR
       ↑方向   ↑原码 ↑位置读数 ↑纠偏 ↑真正下发到四个轮子的数        ↑状态
```

状态：`LOCK` / `CORR` / `CROSS` / `LOST` / `STOP` / `ERR`。

> 上电时串口还会打印 `dir=...`、`sensor=...` 和 `sign_yaw=...`，
> 先确认方向选对了、选的是哪块传感器。

## 第一次调：先调该方向的符号

四块灰阶的**安装方向不同**，同一个 `E` 在四个方向上可能要求相反的转向。
所以程序给每个方向留了一个独立的符号宏：

```c
#define TRACE_SIGN_FRONT    (-1)   /* 2026-10-20 实车验证过 */
#define TRACE_SIGN_BACK     (-1)
#define TRACE_SIGN_LEFT     (-1)
#define TRACE_SIGN_RIGHT    (-1)
```

调法（每个方向单独做）：

1. 把线放在该方向对应的灰阶下面，给车一点速度。
2. 看车是**往线上扭**，还是**越走越偏、斜着冲出去**。
3. 越走越偏 → 把该方向的宏翻成 `+1`，重烧，再试。
4. 别的方向的宏不用动。

四个方向的符号当前都已实车验证为 `-1`。只有更换模块、改变安装方向或重新接线后，
才需要重新确认对应方向的符号。

### `TRACE_BLACK_LEVEL` 只影响路口

灰阶数字量里「黑」对应 `0` 还是 `1`，默认按原工程取 **`0`**。
它**只**用于「压在横向线上不转向」这一条，不影响正常纠偏。设反了的症状：

- 偏到一边、眼看要出线了还不转（把「一侧全白」误判成路口）；
- 或者压在横线上时莫名其妙拐一下。

判据看串口状态：线压在横向黑线上时应该是 `CROSS`，不是就改成 `1`。
四个方向共用这个宏（四块是同一型号）。

## 参数表

| 宏 | 默认 | 作用 |
|---|---|---|
| `TRACE_DIR` | `TRACE_DIR_FRONT` | **选方向，只改这一行** |
| `TRACE_SIGN_FRONT` | `-1` | 前进方向纠偏符号（已实车验证） |
| `TRACE_SIGN_BACK` | `-1` | 后退方向纠偏符号（已实车验证） |
| `TRACE_SIGN_LEFT` | `-1` | 左移方向纠偏符号（已实车验证） |
| `TRACE_SIGN_RIGHT` | `-1` | 右移方向纠偏符号（已实车验证） |
| `TRACE_CRUISE` | `15` | 基础速度。太小克服不了静摩擦 |
| `TRACE_K` | `8` | 纠偏增益 ÷8。8 = 纠偏量等于 `E` |
| `TRACE_MAX` | `5` | 纠偏限幅，**必须 < `TRACE_CRUISE`**（有 `#error`） |
| `TRACE_DEADBAND` | `2` | 死区（权重单位，约 ±5mm） |
| `TRACE_TICK_MS` | `20` | 控制周期 |
| `TRACE_LOST_MAX` | `100` | 丢线后继续走 100 × 20ms = 2s |
| `TRACE_BLACK_LEVEL` | `0` | 「黑」对应的 bit 值，只给路口判据 |
| `TRACE_PRINT_EVERY` | `25` | 每 25 个周期打一行串口 |
| `TRACE_DEBUG` | `1` | 0 = 串口不出声 |
| `TRACE_RETRY` | `3` | 一次下发失败后的重试次数 |

> `TRACE_MAX < TRACE_CRUISE` 是编译期检查。对所有方向都成立：
> 前进时保证 `15 - 5 > 0`，不会出现「只有一侧轮子转」。

## 停下来还不对，按这个顺序查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 上电不走、红灯常亮 | 选中的灰阶没读到线 | 把线放到对应传感器下面；看串口 `raw` 是不是 `00`/`FF` |
| 红灯常亮、串口 `raw 00` 或 `FF` | 该灰阶不在线 / I²C 没通 / 全黑全白 | 查对应引脚；把车挪到线上 |
| 红灯慢闪、串口不打印 | 该灰阶 `Init()` 的 PING 没过 | 查供电和接线 |
| 车往反方向走 | 方向宏选错，或基础组合不对 | 看串口 `dir=...`；对照轮速组合表 |
| 能走但越走越偏 | 该方向的 `TRACE_SIGN_xxx` 反了 | 翻该方向的符号 |
| 走起来画龙 | 增益太大 | `TRACE_K` 从 8 减到 6 |
| 纠偏反应太慢 | 增益太小 | `TRACE_K` 加到 12，或死区减到 1 |
| 只有一侧轮子转 | `m203/m204` 或 `m201/m202` ≤ 0 | 先把 `TRACE_MAX` 调小 |
| 路口疯狂拐一下 | `TRACE_BLACK_LEVEL` 反了 | 改成 `1` |
| 双灯急闪 | I²C 写驱动板失败 | 查 PF5/PF6；驱动板供电 |

## 这个工程里有什么

```
TraceTest\
    tracetest_main.c      测试程序（GBK + CRLF，和工程里其它 .c 一致）
    TraceTest.uvprojx     工程文件，文件清单沿用 MoveTest（少 trace.c/move.c/plan.c）
    TraceTest.uvoptx      调试器配置（ST-Link / SWD）
    Obj\TraceTest.hex     编译产物（当前是 TRACE_DIR_FRONT 那一版）
```

源文件里自带了一份 `reverse()`：工程清单里的四块灰阶驱动
`B/F/L/R_GREY_driver.c` 都调用它，而它本来定义在 `APP\trace\trace.c` ——
那个文件不在本工程里。删掉就会重现 `L6218E: Undefined symbol reverse`。

> 工程清单里仍然带着四块灰阶驱动，但本程序**只初始化选中的那一块**，
> 另外三块不接线也不影响运行。

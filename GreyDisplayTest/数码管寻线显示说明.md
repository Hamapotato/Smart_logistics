# GreyDisplayTest —— 四方向八路灰度数码管显示

> 工程：`GreyDisplayTest\GreyDisplayTest.uvprojx`  
> 主程序：`GreyDisplayTest\grey_display_main.c`  
> 当前方向：前向  
> 协议：Yahboom 官方 I2C（数据寄存器 `0x30`）

## 1. 功能

程序只读取选定方向的一块亚博 `YB-MUX04-2.0` 八路灰度，并在 TM1650
数码管上显示检测到黑线的路号。

当前第 1、8 路已停用，只显示和参与判断 `L2-L7` 六路：

```c
bits &= GREY6_ACTIVE_MASK;   /* 0x7E */
```

- 不初始化电机；
- 不驱动底盘；
- 不初始化红外或舵机；
- 只做灰度读取和数码管显示。

例如检测到 2、6、7 路为黑，数码管显示：

```text
267
```

数码管右对齐显示，最多显示 4 路。全白、读取失败或超过 4 路为黑时，
数码管清空。

## 2. 当前前向测试

源码：

```c
#define GREY_TEST_DIR GREY_DIR_FRONT
```

前向模块：

| 项目 | 配置 |
|---|---|
| 协议 | 亚博 YB-MUX04-2.0 |
| SCL | `PB13` |
| SDA | `PB14` |
| I2C 地址 | `0x12` |
| 数据寄存器 | `0x30` |
| 校准寄存器 | `0x01`（只写） |
| 显示顺序 | 左到右 `1..8` |

上电后必须先等待至少 `20 s` 让探头稳定，再进行读取。

## 3. 四方向切换

修改：

```c
#define GREY_TEST_DIR GREY_DIR_FRONT
```

可选值：

| 宏 | 方向 | SCL / SDA |
|---|---|---|
| `GREY_DIR_FRONT` | 前 | `PB13 / PB14` |
| `GREY_DIR_BACK` | 后 | `PD1 / PD2` |
| `GREY_DIR_LEFT` | 左 | `PC8 / PC9` |
| `GREY_DIR_RIGHT` | 右 | `PC3 / PC2` |

所有方向都使用地址 `0x12`、数据寄存器 `0x30`。

## 4. 数据换算

按 Yahboom 官方协议和模块 PCB 丝印：

```c
raw: bit7=X1, bit6=X2, bit5=X3, bit4=X4,
     bit3=X5, bit2=X6, bit1=X7, bit0=X8

黑色探头输出 0，白色探头输出 1。
模块正面从左到右为 L1..L8，背面探头标号从右到左为 X1..X8，
理论上 L1=X8、L2=X7、...、L8=X1。

但是当前实车模块读出的位序与官方理想位序相差一位。经过实测：

```text
L1 黑时，直接反相会错误显示 7
L2 黑时，直接反相会错误显示 6
```

因此 GreyDisplayTest 使用 StraightTest 已验证的换算：

```c
v = reverse(raw);
v = (v >> 1) | (v << 7);
bits = ~v;
```
```

换算后，`bits` 的 bit0 到 bit7 对应正面从左到右的 `L1..L8`，
也就是观察时约定的 `1..8` 路。

## 5. 显示规则

| 灰度结果 | 数码管 |
|---|---|
| 1 路为黑 | 右对齐显示该路号 |
| 2 路为黑 | 显示两个路号 |
| 3 路为黑 | 显示三个路号 |
| 4 路为黑 | 显示四个路号 |
| 0 路为黑 | 清空 |
| 超过 4 路为黑 | 清空 |
| I2C 读取失败 | 清空 |

## 6. 测试方法

1. 打开 `GreyDisplayTest\GreyDisplayTest.uvprojx`；
2. Rebuild；
3. 烧录并复位；
4. 用白纸确认数码管清空；
5. 依次用黑色物体遮挡前向模块 1 到 8 路；
6. 确认遮挡第几路，数码管就显示几；
7. 同时遮挡多路，确认显示的是对应路号组合；
8. 前向通过后，再把 `GREY_TEST_DIR` 切成后、左、右分别测试。

## 8. 官方资料结论

本地官方资料：

```text
F:\BaiduNetdiskDownload\八路巡线红外传感器\
  0.8路巡线模块的使用方法\8路巡线模块的使用方法.pdf
```

官方示例说明：

```text
X1 在黑线上，其他探头在白线上：
B01111111 = 0x7F = 127
```

PDF 中 `B01111111 -> 0x8F` 的 `0x8F` 是笔误，同一行的 `127`
和二进制 `01111111` 都对应 `0x7F`。第二例
`B10101111 = 0xAF = 175` 是正确的。

所以模块原始数据是 `0=黑、1=白`，且 X1 对应 bit7、X8 对应 bit0。
当前实物模块还需要额外循环移位一位，最终采用上面的实测换算。

# 八路巡线传感器 测试流程

> 测试固件工程：**`Test_Grey.uvprojx`**（在项目根目录，和 `Template.uvprojx` 并列）
> 测试源码：`Test_Grey\grey_test_main.c`
> 固件输出：`Test_Grey\Obj\Test_Grey.hex` / `.axf`
> 被测对象：感为科技（GW）8 路 I2C 灰度巡线模块 ×4

**这个工程和比赛固件完全独立**：`Template.uvprojx` 一个字节都没动，输出目录也是分开的
（`Test_Grey\Obj\` vs `Obj\`），所以不存在“测试固件把比赛固件覆盖了”的风险。

---

## 0. 一句话原理

每个模块有 8 路探头，模块通过 I2C 一次性吐出 1 个字节，**bit0..bit7 就是探头 1..8**。
测一个探头好不好的判据只有一个：**在它眼皮底下来回切换黑/白，这一位会不会跟着变。**
一直不变的那一位，就是坏的那一路。

固件做的就是把这件事自动化：逐路打印、并累计每一位自开机以来**翻转过几次**。

## 1. 接线与准备

### 1.1 四条 I2C 总线（本来就是接好的，这里只是备查）

| 方位 | SCL | SDA | 端口 |
|------|-----|-----|------|
| 前 F | PB13 | PB14 | GPIOB |
| 后 B | PD1  | PD2  | GPIOD |
| 左 L | PC8  | PC9  | GPIOC |
| 右 R | PC3  | PC2  | GPIOC |

> 注意右路是 **PC3=SCL、PC2=SDA**，两脚号反过来，和另外三路不一样。
> 如果只有右路出问题，先怀疑这里接反。

四个模块 I2C 地址都是固定的 **0x4F**，靠各自独占一条总线区分，不冲突。

### 1.2 串口（主要观测通道）

| STM32 | USB-TTL |
|-------|---------|
| PA9  | RXD |
| PA10 | TXD |
| GND  | GND |

**19200 / 8 / N / 1**，无流控。串口助手或 VOFA 都行。

### 1.3 供电

板子和传感器都要单独供电，**别靠调试器供电**（4 个模块 + 数码管电流不小，
电压掉了会读出一堆假故障）。

## 3. 第一步：看自检（上电即出）

上电约 0.5 秒后串口吐出自检结果，**这一步先判“模块活没活”**：

```
==============================================
 巡线传感器测试固件   GW 8路 I2C   地址 0x4F
 串口 19200 8N1    数码管 iNNN = 模块i的原始字节
 打印顺序 = 探头1..8，对应原始字节 bit0..bit7
==============================================
[自检]
 F PB13/14 PING=OK   rsp=0x66  scan=1 [0x4F]  fw=0x0A
 B PD1/2   PING=OK   rsp=0x66  scan=1 [0x4F]  fw=0x0A
 L PC8/9   PING=OK   rsp=0x66  scan=1 [0x4F]  fw=0x0A
 R PC3/2   PING=OK   rsp=0x66  scan=1 [0x4F]  fw=0x0A
[自检结论] PING 通过 4/4   四台模块通讯都正常
```

判读：

| 看到 | 含义 | 怎么办 |
|------|------|--------|
| `PING=OK rsp=0x66 scan=1 [0x4F]` | 模块在，地址对 | 正常 |
| `PING=FAIL rsp=0x00`，`scan=0` | 这条总线上**一个设备都没有** | 查该路 SCL/SDA 接线、模块供电、是否插反 |
| `PING=FAIL`，但 `scan=` 有值 | 总线上有设备但地址不是 0x4F | 模块被别人改过地址（本固件不写地址，可用 `0xAD` 命令或厂家工具改回，谨慎操作） |
| `scan=2` 或更多 | 一条总线上挂了两个设备 → 地址冲突 | 检查是否两个模块并到了同一条总线 |
| `fw=0x00` 且后面带 `(读失败)` | 固件版本寄存器读不出来 | 该模块固件/型号可能不同，PING 通就还能用 |
| 某一路整行没有 | 板上没这个方位 → 代码里 UART/时钟没起 | 检查 USART1 接线与供电 |

红 LED 亮 = 至少有一台 `PING=FAIL`（LED 极性可能相反，**以串口为准**）。

## 4. 第二步：逐路判定（核心）

自检只说明“模块能通信”，**不代表 8 路探头都好**。找坏的那一路靠这一段。

### 4.1 输出长这样（每 500 ms 一行/台）

```
[  0]  F PB13/14 raw=0x18  P1..P8= 0 0 0 1 1 0 0 0
       B PD1/2   raw=0x00  P1..P8= 0 0 0 0 0 0 0 0
       L PC8/9   raw=0x24  P1..P8= 0 0 1 0 0 1 0 0
       R PC3/2   raw=0xFF  P1..P8= 1 1 1 1 1 1 1 1
```

- `raw=0x??` 就是那个字节，`P1..P8=` 是按探头顺序展开的 8 位。
- 每 10 轮（约 5 秒）插一段累计统计：

```
--- 翻转统计（自开机累计）  0 = 该路从未翻转，重点怀疑 ---
  F PB13/14 chg 0 0 0 12 9 0 0 0
  B PD1/2   chg 0 0 0 0 0 0 0 0
  ...
（0 表示这一路从开机到现在电平一次都没变过）
```

### 4.2 操作步骤

**关键点：必须让探头下的颜色发生变化，翻转计数才有意义。**
车停在原地不动的话，8 路全都不会翻转，看不出任何东西。

1. **先把模块底下清干净**（白纸 / 白地板上，或者把车架空、探头对着白纸），
   让串口稳定输出若干轮，然后看一次统计。
2. 用一条**黑胶带 / 黑色卡纸 / 记号笔**，**从模块的一端匀速划到另一端**，
   划过 8 个探头。来回划 3～5 遍。
3. 再看统计。正常情况下，**划过的那一路 `chg` 计数应该明显上涨**（每划一遍涨 1～2）。

### 4.3 记录表（照着填）

把「白底时的值」和「黑线划过后」对比着填：

| 模块 | 探头 | 白底 P | 黑线划过 P | chg 累计 | 翻转了吗 | 结论 |
|------|------|--------|-----------|---------|---------|------|
| F 前 | 1 | | | | | |
| F 前 | 2 | | | | | |
| F 前 | 3 | | | | | |
| F 前 | 4 | | | | | |
| F 前 | 5 | | | | | |
| F 前 | 6 | | | | | |
| F 前 | 7 | | | | | |
| F 前 | 8 | | | | | |
| B 后 | 1..8 | | | | | |
| L 左 | 1..8 | | | | | |
| R 右 | 1..8 | | | | | |

**结论规则：**

- `chg` 明显上涨 → 这一路**正常**。
- `chg` **一直是 0**，而同一个模块别的探头都在涨 → 这一路**坏了**（或者被挡、被焊锡连住、探头上落了脏东西）。**这就是要找的那一路。**
- 整个模块 8 路的 `chg` 全是 0，而别的模块在涨 → 这个**模块整体**有问题（供电、贴得太高/太低、或者模块本身坏了）。
- 所有模块的 `chg` 全是 0 → **你划的东西没进到探头视野里**，不是故障。先把探头贴近纸面（模块离地高度通常要 5～15 mm，太高就读不到）。

### 4.4 探头顺序怎么对到实物

打印顺序是探头 1..8 = bit0..bit7，但**哪个物理端是“探头 1”只有厂家知道**。
做法：把黑线从模块**左端**慢慢划到**右端**，看串口里**哪一个位置先变**——
先变的那个位置就是左端那一路。在模块上用记号笔标上 `1` 和 `8`，以后对照方便。

> 排查完记得把标记和本表留档，换模块后不用重测。

## 5. 备用通道：数码管

没接串口时看数码管。它轮换显示四台：

```
iNNN      i = 模块号 (1=前F / 2=后B / 3=左L / 4=右R)
          NNN = 该模块原始字节的十进制
```

例：`1024` = 前模块 raw=24 = `0x18`；`4255` = 右模块 raw=255 = `0xFF`。

每 1 秒换一台（前 → 后 → 左 → 右）。绿 LED 每 500 ms 翻转 = 心跳（说明程序在跑）。

数码管只能看数值、看不到“翻转过没有”，所以**定位坏路还是得接串口**。

---

## 6. 可选：模拟量（实验性）

每 20 轮（约 10 秒）会插一段逐路模拟量：

```
--- 模拟量快照 0xB0+n（实验性，读完立刻切回数字模式）---
 F PB13/14 012 008 009 190 200 011 007 006
（值域 0..255；某一路恒为 0 或恒为 255 且不随黑线变化 = 可能坏了）
```

用 `0xB0+n` 寄存器逐路读反射强度，比“翻转计数”更直接：**坏的那一路通常卡死在 0 或 255**。

> ⚠️ 这一段是**实验性的**：本工程既有代码从没用过这些寄存器，协议是按
> `GREY_driver.h` 的注释实现的。如果它打出一串 `NACK`、或者打完之后主循环的读数变乱，
> 就把 `grey_test_main.c` 顶部的 `#define GREY_TEST_ANALOG 1` 改成 `0` 重新编译，其余功能不受影响。

## 7. 这个固件**不会**做的事（故意的）

为了不破坏比赛固件正在用的模块参数，本固件**绝不发送**：

| 命令 | 作用 | 为什么避开 |
|------|------|-----------|
| `0xD0` | 黑场标定 | 会覆盖模块里现存的黑场基准 |
| `0xD1` | 白场标定 | 同上，白场基准 |
| `0xC0` | 模块重启 | 参数可能掉 |
| `0xAD` | 改 I2C 地址 | 改了就找不回来了 |

**如果测完发现其实是标定漂了**（不是硬件坏），那就需要在比赛固件里补一段标定流程，
或者用厂家上位机重标。那是另一件事，别在排查阶段顺手做——先把“哪一路坏”确定下来。

## 9. 速查：现象 → 结论

| 现象 | 结论 | 下一步 |
|------|------|--------|
| 四台全 `PING=OK`，逐路 `chg` 也都涨 | 传感器全好 | 问题不在巡线模块，回头查 `Control_Data_Process()` 的判线逻辑 |
| 某一台 `PING=FAIL scan=0` | 那台模块/那条总线断了 | 查接线、供电、模块是否插反 |
| 某一台 PING 通，但 8 路 `chg` 全 0 | 那台模块整体读不到线 | 查安装高度、模块是否对着反光面、模块本身 |
| 某台只有某一路 `chg` 恒 0 | **就是这一路坏了** | 换模块（或那一路探头）；临时可在代码里屏蔽这一路 |
| 全部 `chg` 恒 0 | 探头没贴近被测面 | 降低安装高度 / 换对比更强的黑白 |
| 某台 `scan=` ≥2 | 两模块挂同一条总线 | 拆开，一总线一模块 |
| 数码管不变、绿 LED 不闪 | 程序没跑起来 | 查供电/BOOT0/是否烧错工程 |
| 上电数码管 `0002` | **烧成比赛固件了**（`0002` 是 Template 里写死的画面） | 重新烧 `Test_Grey.uvprojx` |

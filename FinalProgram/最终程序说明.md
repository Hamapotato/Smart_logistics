# FinalProgram v2 —— 去程记录、投递与返程动态避障

> 更新日期：2026-10-28  
> 工程：`FinalProgram\FinalProgram.uvprojx`  
> 主程序：`FinalProgram\final_main.c`  
> 当前状态：红方、蓝方配置均编译通过，尚未实车验证

## 1. 程序目标

本工程把以下部分合并成一个独立比赛程序：

1. IRTest 的八路红外障碍检测；
2. NodeTest 的四方向节点间移动、灰度循迹和节点停车；
3. 8×5 节点地图上的 BFS 路径规划；
4. 去程实际路线记录、终点投递占位和返程路径恢复。

场地和坐标定义见：

```text
..\场地网格与四角巡线理解.md
```

基本模型：

```text
X = 0..7，共 8 列
Y = 0..4，共 5 行
车头固定朝 +Y
```

## 2. 红方和蓝方选择

|---|---|---|
| 红方 | `(7,0)` | `(0,4)` |

## 3. 完整任务流程

```text
上电初始化
  |
等待 1000 ms
  |
去程：当前节点四侧红外扫描
  |
更新 blocked[8][5]
  |
从当前节点到终点执行 BFS
  |
取得路径中的下一节点
  |
调用 NodeTest 前进/后退/左移/右移
  |
检测到下一节点后反向制动并停车
  |
等待 150 ms
  |
更新当前坐标并记录实际路线节点
  |
到达终点
  |
执行投递任务占位
  |
返程：优先按去程路线逆序返回
  |
每个节点停车，四侧红外扫描
  |
下一节点被占用：原地等待，最多 5000 ms
  |
等待超时：把该节点记为固定障碍
  |
从当前节点用 BFS 找回家路线，等长路径优先去程节点
  |
回到起点，红灯常亮并锁停
```

去程每到一个节点都会重新规划。返程优先复用记录的实际路线；只有下一
节点持续被占用时才会更新障碍地图并重新 BFS。

## 4. 四方向与坐标变化

| BFS 路径变化 | NodeTest 模式 | 说明 |
|---|---|---|
| `Y + 1` | `NODE_MODE_FORWARD` | 前进 |
| `Y - 1` | `NODE_MODE_BACK` | 后退 |
| `X - 1` | `NODE_MODE_LEFT` | 左移 |
| `X + 1` | `NODE_MODE_RIGHT` | 右移 |

路径层不执行 90° 转弯。NodeTest 的旋转量 `w` 只用于小幅姿态纠偏，
使车头继续接近 `+Y`。

## 5. BFS 路径规划

障碍地图和原路优先表：

```c
static uint8_t Final_Blocked[8][5];
static uint8_t Final_Preferred[8][5];
```

- `0`：没有确认障碍，按可通过处理；
- `1`：红外已确认该节点有障碍，BFS 不进入。

由于每个相邻节点间移动代价都为 1，使用 BFS 可以得到最短节点路径。
当前 40 个节点的搜索量很小，不需要 D* Lite 或 RRT。

去程按 BFS 选择最短路径，并把每次实际到达的坐标记录到 `route_x/y[]`。
到达终点后，所有去程节点写入 `Final_Preferred[][]`。

返程规则：

1. 当前节点在去程路线中时，优先走向路线中的前一个节点；
2. 如果该方向有车，停车等待，每 `200 ms` 重新读取一次；
3. 连续等待超过 `5000 ms` 仍未清空，把目标节点写成固定障碍；
4. 从当前节点重新执行 BFS；
5. 多条等长路径中优先选择去程经过的节点。

主参数：

```c
#define FINAL_RETURN_WAIT_MAX_MS 5000U
#define FINAL_RETURN_POLL_MS     200U
```

返程时如果 BFS 也找不到回家路径，程序停车并进入错误状态。

## 6. 八路红外障碍检测

使用 IRTest 实测引脚：

| 侧 | 探头 1 | 探头 2 |
|---|---|---|
| 前 | 前左 `FL = PD13` | 前右 `FR = PE12` |
| 后 | 后左 `BL = PB7` | 后右 `BR = PE4` |
| 左 | 左前 `LU = PD14` | 左后 `LD = PB8` |
| 右 | 右前 `RU = PE11` | 右后 `RD = PE3` |

输入为上拉、低电平有效：

```c
#define NODE_IR_ACTIVE_LOW 1
```

同一侧任意一只探头触发，就认为该侧有障碍。连续两个 `20 ms` 周期有效
才确认，约 40 ms 去抖。

E18-D80NK 返回的是数字触发信号，不是模拟距离。检测距离/灵敏度必须用
探头本体电位器标定；修改 `NODE_IR_CONFIRM` 或 `NODE_IR_POLL_MS` 不会
增加探测距离，它们只影响触发确认时间。

四侧映射到节点：

| 红外侧 | 标记的相邻节点 |
|---|---|
| 前 | `(X, Y+1)` |
| 后 | `(X, Y-1)` |
| 左 | `(X-1, Y)` |
| 右 | `(X+1, Y)` |

去程扫描到障碍后直接更新固定障碍地图。返程扫描时，不立即把其他车辆
当成固定障碍，而是先等待其离开；只有等待超时后才把对应节点坐标写入
`Final_Blocked[][]`。

`PB7` 在 IRTest 的历史测试中无响应，但后侧仍可由 `PE4` 触发。正式比赛
前仍应重新检查该路，避免单探头覆盖不足。

## 7. NodeTest 运动控制

本程序直接继承 NodeTest 的控制参数和轮速顺序：

```c
#define NODE_CRUISE            10
#define NODE_TICK_MS           20
#define NODE_TRACK_LAT_K       8
#define NODE_TRACK_LAT_MAX     2
#define NODE_TRACK_YAW_K       8
#define NODE_TRACK_YAW_MAX     1
#define NODE_TRACK_DEADBAND    2
```

移动方向与灰度分工：

| 运动 | 循迹灰度 | 节点检测灰度 |
|---|---|---|
| 前进 | 前、后 | 左、右 |
| 后退 | 后、前 | 左、右 |
| 左移 | 左、右 | 前、后 |
| 右移 | 右、左 | 前、后 |

节点停车：

```c
#define NODE_BRAKE_SPEED 1
#define NODE_BRAKE_MS    400
```

负责节点检测的任意一侧出现 `12` 或 `78` 全黑时，先按当前运动方向给
四轮完整反向 `1` 速，持续 `400 ms`，随后停车。

## 11. 第一次实车测试顺序

1. 确认 `FINAL_TEAM` 选对；
2. 车架空，确认四个方向移动和停车方向；
3. 逐个遮挡前、后、左、右红外，检查串口 `IR F/B/L/R`；
4. 把车放在起点节点；
5. 先不放障碍，确认去程、投递占位、原路返程完整结束；
6. 在去程最短路径节点放障碍，确认前进阶段改道并记录新路线；
7. 在返程路线节点放障碍并保持超过 5 秒，确认标记固定障碍并 BFS 绕行；
8. 确认串口打印的 `OUTBOUND PATH` 和 `RETURN PATH` 坐标正确；
9. 再测试靠近障碍一侧的双探头和 `PB7`；
10. 最后测试红方和蓝方两个起点/终点配置。

## 12. 当前限制

- 本工程尚未实车验证；
- 红外检测距离必须覆盖一个网格间距；
- 当前假设障碍只在节点，不在边中；
- 当前没有多机器人通信；返程依赖停车等待和红外避让；
- 当前只在节点扫描障碍，不在移动途中重新规划；
- 如果终点节点被红外判为障碍，BFS 会报告无路径；
- 当前设备使用 NodeTest 的无编码器开环速度控制；
- 当前使用 Keil 编译宏切换红方/蓝方，不支持上电自动识别队伍；
- 当前版本只覆盖场地导航和避障，抛投/投放机构尚未整合。
